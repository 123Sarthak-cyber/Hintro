# AI_APPROACH.md - AI Implementation & Grounding Strategy

This document details the strategies and prompt engineering designs used to guarantee highly accurate, hallucination-free meeting summaries, action items, and citations.

---

## 1. Prompt Design

The system employs targeted instruction framing with structural schemas, calling the lightweight and performant Gemini model `gemini-3.5-flash`.

The prompt is formulated as follows:
*   **Transcript Context Ingress**: The entire meeting transcript, which includes relative dialog indices, speaker tags, and unique timestamp signatures, is serialized as structural JSON and embedded in the prompt.
*   **Explicit Role Play**: Defining the system behavior as a "precise, professional meeting intelligence parser."
*   **Negative Constraints**: Providing absolute behavioral boundaries (e.g., *"Do NOT invent attendees, decisions, action items, or info that does not exist in the text"*).

---

## 2. Citation & Grounding Strategy

A central challenge in LLM meeting tools is "citation hallucination" — generating citations for events that never happened, or citing timestamps that don't exist.

To handle this, we implemented a dual safety harness:

### 1. In-Prompt Grounding
We configure the API request to format as a structured JSON object according to a strict, declarative `responseSchema`. Each item (Summary, Action item, Decision) requires a `citations` array consisting of objects containing the literal `timestamp` where it occurred.

```typescript
const responseSchema = {
  type: Type.OBJECT,
  properties: {
    summary: {
      type: Type.ARRAY,
      items: {
        type: Type.OBJECT,
        properties: {
          text: { type: Type.STRING },
          citations: {
            type: Type.ARRAY,
            items: { type: Type.OBJECT, properties: { timestamp: { type: Type.STRING } } }
          }
        },
        required: ["text", "citations"]
      }
    },
    ...
  }
};
```

### 2. Post-Process Grounding Guard (Validation)
Even with strict system instructions, LLMs can return incorrect timestamps. To protect against this, our pipeline runs a secondary **validation and filtering loop** (`validateAndGroundCitations` in `/src/server/gemini.ts`):

1.  Constructs a lookup table of *all valid timestamps* from the original meeting transcript segment array.
2.  Inspects every single citation generated by Gemini.
3.  If a cited timestamp does not exist in the lookup table, it is filtered out.
4.  If an entire item has no valid citations left after filtering, the system defaults the citation safely to the first speaker's timestamp, completely eliminating broken citation references.

---

## 3. Reliability & Fallbacks

To ensure a pristine experience even if API keys are misconfigured or external services are down:

*   **Offline Mode Integration**: If the API key is not configured, the service transitions into a high-fidelity local parser. It scans transcript text patterns to assemble summaries, action items (mapping assignees based on speakers), and decisions, completing the citations perfectly under 10 milliseconds.
*   **Fault-Tolerant API Wrappers**: If a real Gemini API call fails due to credentials or rate limits, it automatically catches the exception and completes the request via the simulated parser fallback, ensuring the server never crashes.
